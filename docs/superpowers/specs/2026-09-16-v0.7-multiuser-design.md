# Spec: v0.7.0 多人(登录会话 / Token 管理 / 审计日志 / 全局通知)

## 统一认证模型(核心决策)

所有认证最终都收敛为 **Bearer token**:
- `SCHEDULE_TOKEN` 静态 token(不变,机器对机器)
- **会话 token**:登录接口签发,30 天有效,哈希存 `sessions` 表
- **API token**:设置页生成/吊销,哈希存 `api_tokens` 表

中间件校验顺序:SCHEDULE_TOKEN → sessions(未过期)→ api_tokens → 401。
**开放模式**:`SCHEDULE_TOKEN`、管理员账号均未配置时,登录禁用且全 API 开放(向后兼容)。

## F1 登录会话
- 表:`users(username PK, password_hash)`、`sessions(token_hash PK, created_at, expires_at)`
- 管理员来源:`ADMIN_USER`/`ADMIN_PASSWORD` 环境变量或 config.toml(`admin_user`/`admin_password`);启动时 seed(INSERT OR REPLACE,密码 sha256 十六进制)
- `POST /api/auth/login {username, password}` → 校验 → 签发会话 token(随机 32 字节 hex)→ `{token, expires_at}`;失败 401
- 登录尝试不限速(v0.7 自托管场景,文档注明)
- 前端:401 时弹**登录对话框**(用户名/密码),登录成功自动存 token 并刷新——替换原手填 token 对话框

## F2 Token 管理
- 表:`api_tokens(id PK, name, token_hash UNIQUE, created_at)`
- 端点(需会话/管理员):`GET /api/auth/tokens`(列表,name+created_at,不含明文)、`POST /api/auth/tokens {name}`(生成,明文仅返回一次)、`DELETE /api/auth/tokens/:id`
- 前端:设置对话框(齿轮按钮)→ Token 列表 + 新建(弹明文一次)+ 吊销

## F3 审计日志
- 表:`audit_log(id PK, ts, action, summary)`;记录 create/update/delete/enable/disable/run/import/login
- 记录点:各 API handler 成功路径,`tracing` 同步输出
- `GET /api/audit?limit=100` → 列表;前端设置对话框 "Audit" 标签页展示

## F4 全局通知渠道
- config/env:`NOTIFY_TYPE` + `NOTIFY_URL`(全局默认)
- 任务 `notify_type=none` 时回落到全局渠道(Executor 持有全局配置)

## 依赖
新增 `sha2 = "0.10"`(密码与 token 哈希)。rand 已有(uuid 传递)。

## 冒烟
1. 配置管理员:login 正确/错误密码 → 200/401;会话 token 访问 API ✓
2. 开放模式(无 SCHEDULE_TOKEN 无管理员)→ 全开放 ✓
3. Token 生成 → 用明文访问 ✓ → 吊销后 401 ✓
4. 审计:增删改后 /api/audit 出现记录 ✓
5. 全局通知:任务 notify=none,hook 实收测试/失败通知 ✓
