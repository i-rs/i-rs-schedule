# Spec: v0.10.0 「事件」(Webhook 触发器 / 变量与密钥 / 漏跑检测)

## F1 Webhook 触发器

- 任务可开启入站触发端点 `POST /api/hooks/:task_id/:secret`:
  - `POST /api/tasks/:id/hook` 生成 secret(32 hex,`sha256` 哈希存 `hook_secret_hash` 列),
    明文仅返回一次;重复调用 = 轮换;`DELETE` 关闭。Auth 中间件豁免 `/api/hooks/` 前缀
  - 命中即后台执行(spawn 后立即 202 `{triggered:true}`),复用 max_concurrent / 重试 / 通知 / 审计
  - 插值:shell cmd、http url/body/header 值支持 `{{event.body}}`(截断 10KB)、`{{event.query.x}}`
- 范围裁剪:`{{event.header.x}}` 暂不做(用例少,query+body 覆盖绝大多数)
- 前端:任务抽屉 Webhook 区(开启 → 显示完整 URL 一次 + 复制;已开启 → 轮换/关闭)
- CLI:`task hook <id> enable|disable`

## F2 变量与密钥

- 全局变量表 `variables(key PK, value, is_secret)`;插值 `{{var.key}}` 作用于
  shell cmd、http url/body/header 值;执行时加载一次(每 execution 一次查询)
- **范围裁剪:不做任务级变量**——任务级变量与直接写在命令里完全等价,是假抽象;
  全局变量解决的是跨任务共享(DB 地址、token),这才是真需求(CHANGELOG 注明)
- API:`GET /api/vars`(is_secret 的 value 永不返回)、`POST /api/vars {key,value,is_secret}`、
  `DELETE /api/vars/:key`;导出不含变量(密钥不外泄,导入方自行配置)
- 前端:设置对话框 Variables 标签页(列表/新增/删除;secret 显示 ••••)
- CLI:`var list|set|delete`

## F3 漏跑检测(deadman)

- 任务字段 `missed_alert`(bool,默认 false,仅 cron 任务有意义)
- 后台扫描(`watchdog.rs`,每 60s):
  - 期望时间 = 时区下 now 之前最近的一次 cron 触发点(宽限期固定 5 分钟)
  - now > 期望 + 5min 且该任务在期望时间之后**没有任何 execution 尝试**(含失败)
    → 静默漏跑 → 按任务通知渠道(全局回落)推送 `task_missed` 告警
  - 每个"期望时间"只告警一次(内存抑制表 task_id → 已告警的期望时间)
- 前端:表单通知区加"漏跑告警"复选框;CLI `--missed-alert`
- 定位:补全 v0.1 失败通知的盲区——"该跑没跑"是 cron 最危险的沉默故障

   `{{event.body}}` 插值进 shell 输出;关闭后端点 404
2. 变量:设 `var greeting=hello` → 任务 `echo {{var.greeting}}` 输出 hello;
   secret 变量 GET /api/vars 不回值;删除后插值原样保留 `{{var.greeting}}`
3. 漏跑:开启 missed_alert 的每分钟任务 → 手动 disable 一段时间再观察?不可行——
   改为:任务命令正常、把 next 窗口制造 miss(临时把 grace 逻辑跑通)→ 收到/模拟推送;
   最小验证:watchdog 扫描不误报(正常任务无告警)+ 单元测试覆盖判定函数
