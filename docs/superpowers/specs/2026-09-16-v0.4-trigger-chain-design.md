# Spec: v0.4.0-F1 任务依赖链(成功触发)

轻量编排:A 成功后自动执行 B(单向链,非 DAG)。

## 数据模型
- `tasks` 表新增 `trigger_task_id TEXT NOT NULL DEFAULT ''`(配置在**触发方** A 上:A 成功后执行该 id 指向的任务)
- 幂等迁移(PRAGMA + ALTER,同既有模式)

## 语义与防环
- 触发条件:A 的**最终结果为 success**(重试耗尽后的成功也算)
- 目标任务必须存在且 enabled,否则记 warn 并跳过(不报错——删除被依赖任务时链自然失效)
- **保存时防环**:create/update 时沿 trigger 链最多走 20 步;回到自己 → 400 "circular trigger chain";目标不存在 → 400
- **运行时防环**:执行深度参数(默认 0),链式触发时 +1,超过 10 层记 error 并停止
- 链式触发走完整 `execute_and_record`(B 的重试/通知/自己的链都正常生效)

## 接口
- API:`CreateTaskRequest.trigger_task_id: Option<String>`;空串/缺省 = 无
- CLI:`--trigger-on-success <task_id>`
- 前端:表单 "On Success" 区块,下拉列出**其他**任务(排除自身),默认 None;任务卡显示 Link2 图标(有下游时)

## 冒烟
1. A=`exit 1`(失败)→ B 不触发
2. A=成功 → B 触发(executions 里出现 B 的记录)
3. A→B→A 配置 → 400 环;A→A → 400 自环
