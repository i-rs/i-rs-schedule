# Spec: v0.1.0-F1 失败通知

任务失败/恢复时推送通知到用户配置的渠道。设计要点(路线图已批准)在本文档落地为具体决策。

## 数据模型

`tasks` 表新增两列(存量库需迁移):

- `notify_type TEXT NOT NULL DEFAULT 'none'` — `none` | `webhook` | `feishu` | `dingtalk`
- `notify_url TEXT NOT NULL DEFAULT ''`

**迁移方式**:`PRAGMA table_info(tasks)` 检查列存在,缺失则 `ALTER TABLE ADD COLUMN`(幂等,旧库自动补列)。

## 触发语义

- **失败通知**:execution 最终 `status == "failure"` 且任务配置了通知
- **恢复通知**:本次 `success` 且**上一次**该任务的 execution 为 `failure|interrupted`(重启后首次成功也视为恢复,历史在库里所以跨重启有效)
- 连续 N 次失败阈值:**v0.1 不做**(需要额外状态,推迟到 v0.2 与重试一起设计)
- 通知发送 **fire-and-forget**(tokio::spawn):不阻塞主流程、不产生 execution 记录;发送失败仅 `tracing::warn`

## Payload 格式

通用文本(飞书/钉钉共用,截断 2000 字符):

```
[i-rs-schedule] 任务失败            // 或 任务恢复
名称: {name}
任务ID: {task_id}
状态: {status}
耗时: {duration_ms}ms
输出: {output截断}
```

- `webhook`:POST JSON `{event, task_id, task_name, status, duration_ms, output, exec_id, started_at, finished_at}`(`event`: `task_failure` | `task_recovery`)
- `feishu`:POST `{"msg_type":"text","content":{"text": <通用文本>}}`
- `dingtalk`:POST `{"msgtype":"text","text":{"content": <通用文本>}}`

发送:Notifier 持有独立 `reqwest::Client`(超时 10s);2xx 视为成功。

## 模块与接入

- 新建 `crates/schedule/src/notify.rs`:`Notifier { client }` + `pub fn notify_failure(&self, ctx)` / `notify_recovery(&self, ctx)`(内部 spawn)
- `execute_and_record`(executor.rs)在 update_execution 之后:
  - 失败 → `db.get_previous_execution(task_id, &exec_id)` 查前一条状态,若配置了通知则 `notify_failure`
  - 成功且前一条为 failure/interrupted → `notify_recovery`
- `main.rs` 构造 `Arc<Notifier>` 传入 executor(或挂在 Executor 内——**决策:挂在 Executor 内**,execute_and_record 已持有 self,改动面最小;Executor::new() 创建 Notifier)

## API / CLI / 前端

- `CreateTaskRequest` + `notify_type: Option<String>` / `notify_url: Option<String>`;`build_task` 校验:`notify_type != none` 时 url 必填;类型必须在枚举内(否则 400)
- CLI:`task add` 增 `--notify-type` / `--notify-url`
- 前端表单新增 "Notification" 区块:Select(none/webhook/feishu/dingtalk,中文标签 通知/Webhook/飞书/钉钉)+ URL Input(选 none 时隐藏);任务卡有通知配置时标题旁显示铃铛图标(Bell)
- `Task`/`CreateTaskPayload` 类型同步字段

## 验证

1. `cargo build` + clippy 零 warning + fmt;`pnpm build` + lint
2. 冒烟:本地 python echo server 收 webhook → 创建 `notify_type=webhook` 的 shell 任务(`exit 1` 制造失败)→ run → echo server 收到 `task_failure` payload;再跑一次成功 → 收到 `task_recovery`
3. 飞书格式:payload 断言 `msg_type=text`
4. 存量库迁移:老 db 启动不报错,新列存在
