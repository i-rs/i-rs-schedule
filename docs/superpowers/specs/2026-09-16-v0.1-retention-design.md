# Spec: v0.1.0-F3 执行记录保留

防止 `task_executions` 无限增长撑爆磁盘。

## 设计

- 环境变量 `RETENTION_DAYS`:保留天数,**默认 30**,`0` = 永久保留(禁用清理)
- 清理时机:
  1. **启动时**(`main.rs`,Db 初始化后):删除 `started_at < now - N days` 的记录,删除行数 > 0 时记 `info!` 日志
  2. **每日定时**:tokio::spawn 一个循环,`tokio::time::interval(24h)` 周期调用同一清理函数
- 删除条件按 `started_at` 字符串比较:时间戳是 ISO-8601 定宽格式(`%Y-%m-%dT%H:%M:%S%.3fZ`),字典序即时间序;SQL 参数为 `now_iso()` 减去 N 天后的同格式字符串
- DB 方法:`Db::purge_executions_older_than(cutoff_iso: String) -> Result<u64>`(spawn_db 包裹)
- 兼容:极老的 SQLite 默认格式记录(`datetime('now')`,无 T/Z)字典序不同,可能漏删——不影响正确性,后续自然被清理覆盖;v0.1 不做格式迁移

## 验证

1. 插入一条 40 天前的 execution + 一条当前 execution,`RETENTION_DAYS=30` 启动 → 老记录被删、新记录保留、日志显示 affected=1
2. `RETENTION_DAYS=0` → 两条都保留
3. build + clippy 零 warning
