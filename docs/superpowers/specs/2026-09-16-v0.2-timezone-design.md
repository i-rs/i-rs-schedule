# Spec: v0.2.0-F1 时区支持 + next_run_at

## 背景

cron 目前按 UTC 计算,"每天 9 点"实际是北京 17 点。任务级时区是中文用户最痛的点。next_run_at 依赖时区计算,一并实现并用它验证时区正确性。

## 时区支持

- 新依赖 `chrono-tz = "0.10"`(纯数据 crate,与 chrono 0.4 配套)
- `tasks` 表新增 `timezone TEXT NOT NULL DEFAULT 'UTC'`(幂等迁移,同 F1 模式)
- `Task.timezone: String`;默认 `UTC` 保证存量兼容
- `schedule.rs`:
  - `pub fn validate_timezone(s) -> Result<(), String>`:`s.parse::<chrono_tz::Tz>()` 失败报错(创建/更新时 400)
  - `next_delay(&self, tz: Tz)` / `remaining_delay(&self, created_at, tz)`:签名加 tz 参数;cron 用 `schedule.upcoming(tz)`;Once 不受时区影响但仍透传
- `scheduler.rs`:insert/load/run 重排时从 `task.timezone` 解析 `Tz`(解析失败 → UTC + warn,防御绕过校验的写入)
- api.rs:`CreateTaskRequest.timezone`,`build_task` 调 `validate_timezone`(400);`Task::new` 默认 UTC
- CLI:`--timezone`(默认 UTC);前端表单:常用时区 Select(UTC/Asia/Shanghai/Asia/Tokyo/Asia/Hong_Kong/Singapore/Europe/London/Berlin/New_York/Los_Angeles)

## next_run_at

- `schedule.rs` 新增 `pub fn next_run_at(task: &Task) -> Option<String>`:
  - disabled → None
  - cron → `schedule.upcoming(tz).next()` 转 UTC ISO 字符串
  - once → `created_at + delay_secs`,已过期则 None
- API:`GET /api/tasks` 与 `GET /api/tasks/:id` 响应包一层 `TaskWithNext`(flatten task + `next_run_at`),List/Get/POST/PUT 响应统一(POST/PUT 返回的 task 也计算)
- 前端:任务卡 schedule 徽章旁显示 "in 5m"(复用相对时间格式,阈值 "now" 显示 "due");disabled 不显示

## 验证

1. 单元级:上海 cron "0 0 9 * * *" 的 next_run_at 的 UTC 小时 == "01"(冒烟时通过 API 断言)
2. 创建非法时区 → 400;旧库启动自动补列
3. build/clippy/fmt + pnpm build/lint 全绿;前端 DOM 显示 "in Xm"
