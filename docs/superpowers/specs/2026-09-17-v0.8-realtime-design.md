# Spec: v0.8.0 「实时」(实时输出流 / 输出上限 / 推送式刷新 / PWA)

## 关键决策:长轮询替代 SSE(框架约束下的等价体验)

desirable 1.2~1.7 的响应体类型固定为 `hyper::Response<Full<Bytes>>`(全量缓冲),
**不支持流式响应体,真 SSE 不可行**。改用 **HTTP 长轮询(long-polling)**:

- 服务端 hold 请求最长 25s,期间有新数据立即返回,否则超时返回空增量(客户端无缝续轮)
- 体验与 SSE 等价(亚秒级上屏),且**复用现有 Auth 中间件**(Bearer header / cookie 直接可用,
  无需 roadmap 里预设的一次性 ticket),代理/反代友好
- roadmap 措辞相应更新为"长轮询实时流"

## F1 输出持久化上限 `MAX_OUTPUT_KB`

- config/env:`MAX_OUTPUT_KB`(config.toml `max_output_kb`),默认 64,0 = 不限
- 累积策略(内存有界,与输出总量无关):head 固定保留前 32KB,tail 滚动保留后 32KB
  (cap 为上限一半一半;cap < 64KB 时按比例)
- 超限时持久化输出 = head + `\n…[truncated N bytes]…\n` + tail;HTTP `resp.text()` 同样处理
- 行为变更:Shell 输出从"成功只存 stdout / 失败只存 stderr"改为 **stdout+stderr 按到达顺序合并**
  (实时视图本来就是两路合并;触发链 `{{trigger.output}}` 拿到合并输出,调试更好)

## F2 实时输出流(后端)

- `live.rs`:`LiveOutput { head, tail, total, version, done }` + `watch::channel<u64>` 变更通知;
  `LiveRegistry = Mutex<HashMap<exec_id, Arc<LiveOutput>>>`(执行结束移除条目)
- Executor Shell 路径重写:`Command::spawn()` + stdout/stderr 两路并发增量读取 →
  写入 LiveOutput(每 chunk version+1 并 notify);整体套 `tokio::time::timeout`,
  超时 kill 子进程,输出追加超时提示。HTTP 任务无流式概念(响应体一次到达),不加 live 条目
- 端点 `GET /api/executions/:id/live?cursor=<version>`(走现有 Auth):
  1. live 条目存在:version > cursor → 立即返回快照;否则 watch 等待(25s 超时)
     → 返回 `{version, output, total, status:"running", done:false}`
  2. 条目不存在(已完成 / HTTP 任务 / 进程重启):查 DB——
     finished → `{status, output, done:true}`;running(HTTP)→ `{status:"running", output:null, done:false}`
- 前端 cursor 语义:每次拿全量快照(≤64KB),直接整体渲染,不做增量拼接(简单可靠)

## F3 推送式刷新(事件长轮询)

- `Events`:全局 `watch::channel<u64>` 计数器;executor 在 create_execution /
  update_execution 后 +1;任务 CRUD / enable / disable / run / import 也 +1(UI 全自刷新)
- 端点 `GET /api/events?cursor=<n>`:同款长轮询(25s),返回 `{cursor}`;前端变化即触发对应页面 refetch
- 前端 `useEvents` hook:循环长轮询(失败退避 2s 重连,断线自愈);接入
  Executions / Tasks / Dashboard / Drawer;Dashboard 30s `setInterval` 退役

## F4 PWA

- `public/manifest.webmanifest`(name/short_name/theme_color/background_color/display:standalone/icon)
- 图标:由 `favicon.svg` 生成 192/512 PNG(`apple-touch-icon` 180)
- `public/sw.js` 极简 service worker:静态资源(构建产物 hash 文件名)cache-first;
  `/api/*` 与 live/events 长轮询一律 network-only(不缓存);版本化缓存名,activate 清旧缓存
- `index.html` 补 manifest link + theme-color + apple-touch-icon;`main.tsx` 注册 SW
  (仅 production,`import.meta.env.PROD`)

## 冒烟

1. 输出上限:shell 产出 1MB → 落库输出含 truncated 标记且 ≤ 64KB+标记;MAX_OUTPUT_KB=0 不截断
2. 实时流:建 shell 任务 `for i in 1..10; do echo $i; sleep 1; done` →
   另一终端轮询 /live,cursor 递增、输出逐步增长;结束后 done:true、DB 记录完整
3. 事件刷新:curl /events 挂起 → 触发一次任务 run → 25s 内返回新 cursor;
   前端执行列表无需手动刷新即出现新记录
4. 认证:设置 SCHEDULE_TOKEN 后 /live 与 /events 无 token → 401;带 token → 200
5. PWA:pnpm build 后 dist 含 manifest/sw.js/图标;Lighthouse 或手检 manifest 可解析
6. 回归:cargo test 全绿;既有任务 CRUD / 链式触发 / 通知不受影响
