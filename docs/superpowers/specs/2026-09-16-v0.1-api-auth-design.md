# Spec: v0.1.0-F2 API 认证

可选的 Bearer Token 认证:`SCHEDULE_TOKEN` 未设置时完全开放(本机模式,向后兼容);设置后所有 `/api` 请求必须携带 `Authorization: Bearer <token>`,否则 401。

## 后端

- api.rs `build_router` 中,读 `SCHEDULE_TOKEN` 环境变量(非空才启用),用 desirable 的 `router.with(闭包 middleware)` 注册(框架对 Fn 提供了 Middleware blanket impl,无需 async-trait)
- 闭包内检查 `req.inner.headers().get("authorization")` 是否等于 `Bearer {token}`;失败返回标准信封 `{code:401, message:"unauthorized"}`(复用 err_msg)
- 401 不做 constant-time 比较(自托管单用户场景,文档注明)

## CLI

- 全局 `--token` 参数,优先级:`--token` > `SCHEDULE_TOKEN` 环境变量
- 用 `reqwest::Client::builder().default_headers()` 一次性注入,所有请求自动携带

## 前端

- `api.ts`:请求前从 `localStorage("schedule_token")` 读 token,有则注入 Authorization header;响应信封 `code === 401` 时 `window.dispatchEvent(new CustomEvent("auth-required"))` 并抛错
- 新建 `AuthDialog`:监听 `auth-required` 事件弹出,输入 token 保存到 localStorage 后关闭(下次请求自动带上);App.tsx 挂载

## 验证

1. 带 `SCHEDULE_TOKEN` 启动:无 header → 401;正确 header → 200;错误 token → 401
2. 不带环境变量启动:无 header 也可访问(兼容)
3. CLI:配 token 访问成功;未配 → 报 401 错误且 exit 1
4. cargo build/clippy 零 warning;pnpm build/lint 通过
