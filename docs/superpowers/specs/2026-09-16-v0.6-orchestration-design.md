# Spec: v0.6.0 编排补全(触发策略/多下游/传参/克隆)

## F1+F2 触发策略 + 多下游

- `tasks` 新列:`trigger_task_ids TEXT NOT NULL DEFAULT '[]'`(JSON 数组)、`trigger_on TEXT NOT NULL DEFAULT 'success'`(success/failure/always)
- 迁移:补列后,若旧列 `trigger_task_id` 非空则将其并入 `trigger_task_ids`(一次性数据迁移,旧列保留不删)
- `Task`:`trigger_task_ids: Vec<String>` + `trigger_on: String`(替换原 `trigger_task_id`)
- 执行策略:final_exec.status 匹配策略(success→成功 / failure→失败 / always→恒)即逐个触发下游(各自独立 spawn,depth+1,上限 10)
- 校验:create/update 时对每个目标走链检查(存在/自环/循环 ≤20);trigger_on 白名单
- CLI:`--trigger-on-success` 改为逗号分隔多值;新增 `--trigger-on`(默认 success)
- 前端:On Success 区块改为 策略下拉(成功时/失败时/总是)+ 其余任务的**复选列表**;卡片 Link2 图标按数组非空显示

## F3 上下游传参

- `TriggerContext { output: String, status: String }`(触发方的最终输出与状态)
- 链式触发时传入 execute;**仅 Shell 命令**做插值:`{{trigger.output}}`、`{{trigger.status}}`(output 截断 10000 字符防超大命令行);HTTP 任务忽略
- 非链式触发(trigger=None)不做替换

## F4 任务克隆

- 纯前端:卡片菜单"Clone"→ 以现有配置调用创建 API,name 加 " (copy)",id/时间由服务端生成;成功后刷新

## 冒烟

1. A(成功)触发 B、C 两个下游 → executions 出现三条
2. trigger_on=failure 的链只在失败时触发
3. B 命令含 {{trigger.output}} → 收到 A 的输出
4. A→B→A 循环 → 400;克隆任务出现且配置一致
