# Spec: v0.9.0 「秩序」(并发互斥 / 标签 / 维护模式 / 自动备份)

## F1 并发与互斥

- 任务级 `max_concurrent`(INTEGER,默认 1,0 = 不限并行):
  - 达到上限时**跳过并落库 `skipped` 记录**(output 注明 "overlaps with a previous run"),
    不排队——定时任务重叠执行多数有害(重复扣款/通知),skip 是安全默认
  - queue 模式推迟:真实需求应先修超时/调度间隔,持久化队列的复杂度不值得(CHANGELOG 注明)
  - 计数器在 Executor 进程内:`Mutex<HashMap<task_id, usize>>`;手动 /run、cron、链触发
    共用 execute_and_record 入口,全部受控;**重试退避期间占住槽位**(上一触发仍算在途)
  - 全局兜底:`tokio::sync::Semaphore`,`GLOBAL_MAX_CONCURRENCY`(默认 32),超限**等待**
    (全局层排队,防资源耗尽;与任务层 skip 语义不同层)
- 前端:skipped 琥珀色徽章、执行过滤 Tabs 增加 Skipped;任务表单 Advanced 加并发数输入
- CLI:`task add/update --max-concurrent`

## F2 标签系统

- `tasks.tags` TEXT(JSON 数组),PRAGMA 迁移补列;不建关联表(自托管规模,查询在应用层)
- API:create/update 接受 `tags: Vec<String>`;列表自然返回;标签集合前端从任务列表派生,不加端点
- 批量操作:`POST /api/tasks/batch {ids, action: enable|disable|delete}` → 逐个复用既有
  逻辑(含 scheduler 控制命令与审计);返回 `{changed}`
- 前端:任务卡复选框多选 → 浮动批量操作条(启用/禁用/删除,删除需确认);标签过滤下拉;
  标签色由名称 hash 确定性取色(不落库)
- 导出/导入自然含 tags
- CLI:`task add/update --tags "a,b"`

## F3 维护模式

- `settings(key PK, value)` 表(幂等建表),键 `maintenance`
- API:`GET /api/maintenance` → `{enabled}`;`POST /api/maintenance {enabled}` →
  持久化 + 广播 `ControlCmd::SetMaintenance(bool)` + events.bump
- Scheduler:`paused` 标志;**暂停期间到期任务不执行**:
  - cron → 计算下一次未来触发时间重新入队(错过的不补发)
  - once(过期)→ 落库 `skipped` 记录(missed during maintenance),移出队列
  - 在途执行不中断;恢复后按 next_run 正常续跑
  - 手动 /run 不受影响(显式人工动作)
- 前端:激活时顶栏琥珀色横幅(含"恢复调度"按钮);设置对话框加 Maintenance 开关
- CLI:`maintenance status|on|off`
- `/healthz` 附带 `{maintenance}` 状态

## F4 自动备份

- 配置:`BACKUP_DIR`(空 = 关闭)、`BACKUP_KEEP`(默认 7)
- 每日 + 启动时:`VACUUM INTO '<dir>/schedule-backup-<ts>.db'`(在线备份,不锁库);
  超出保留份数删最旧;失败仅 warn 不影响服务
- `/healthz` 附带 `{last_backup}`(最近成功时间,进程内共享状态)

## 冒烟

1. 并发:max_concurrent=1 任务 cmd=`sleep 2`,启动后立即手动 run 两次 → 第二次 skipped 落库;
   max_concurrent=0 时两次都成功
2. 标签:建两个任务打标签 → batch disable → 均变 disabled;按标签过滤生效
3. 维护:开启 → cron 任务到期不执行(等 1 个周期);once 到期任务被记 skipped;
   关闭 → 恢复;顶栏横幅出现/消失;healthz 反映状态
4. 备份:BACKUP_DIR 临时目录 → 启动即生成备份文件;healthz 有 last_backup;BACKUP_KEEP=2 时旧文件被清理
5. 回归:cargo test 全绿;既有任务 CRUD/链/通知不受影响;前端 build/lint 通过
